# Security

inkmoth lets a language model choose which URLs to fetch after reading untrusted web pages. The design
assumes some of those pages are hostile.

## Fetching (`netguard.py`, `transport.py`, `fetch.py`)

- Public fetches use a dedicated HTTPCore transport. It resolves the hostname, checks **every** DNS answer
  immediately before dialing a numeric address, and keeps the original hostname for TLS verification, SNI and
  `Host`. DNS rebinding between the check and the connection is therefore not a way in.
- Nonpublic destinations are rejected: loopback, private ranges, link-local, CGNAT, IPv6 translations of
  internal IPv4 addresses, `.local`/internal names, URLs with credentials, ambiguous URLs, and ports other than
  80/443. Every redirect hop is checked again (at most five).
- Search results pointing at internal addresses are removed before the model sees them, and page text that a
  search provider supplies for such URLs is never cached.
- Environment proxies are ignored by the model, search and fetch clients.
- Injected HTTP clients are trusted dependencies. Production fetch clients must come from
  `fetch.public_client()` or keep equivalent connection-level enforcement.

The model and search endpoints are **trusted configuration** and may be private addresses.

## Parsing (`extract.py`)

- Downloads stream with a byte cap (2 MB for HTML/text, 50 MB for PDFs by default). Compressed responses are
  rejected even if the server ignores the request for identity encoding, so a decompression bomb never
  reaches a decompressor. Unsupported content types are rejected before the body is read; a generic
  `application/octet-stream` body is accepted only if its first bytes are `%PDF-`.
- Extraction runs in a disposable subprocess that is killed on timeout or cancellation. On Unix it also has a
  512 MiB address-space limit and a CPU limit equal to `extraction_timeout` (60 s by default). Extracted text
  is capped at 5 M characters.
- This is a **resource boundary, not a sandbox**. The worker runs with your user's permissions. That is why
  the PDF parser is pure-Python pypdf rather than a faster C/C++ library: a malicious PDF can waste CPU until
  the limit, but memory-safety bugs are off the table. If you swap in a native parser, consider running the
  worker under an OS sandbox.

## Prompts and evidence

- Prompts tell every role to treat pages, quotes and findings as data. Prompt injection is still possible;
  the evals include an adversarial fixture with answer-poisoning and loopback-fetch instructions.
- What an injected page can do to the report is limited by provenance checks: every cited claim needs a
  verbatim quote from fetched text, and citations, the bibliography and the `†` single-site markers are
  generated by the application. Rejected claims (which may contain injected text) never reach a later prompt;
  later researchers only see source IDs and counts.
- With a search provider that returns page text (Tavily), quotes are verified against the provider's copy of
  the page. You are trusting the provider's extraction as you would trust its ranking.
- Search queries and fetched URLs leave your machine. Only ask questions whose content is fine to send to your
  search provider and to the sites the model visits.
- Report Markdown is untrusted content. Render it safely (no raw HTML) in any UI.

## MCP server

The MCP server runs with your environment and permissions and does whatever research the host asks for.
`get_report` turns a run ID into a file name, so it only accepts 32 lowercase hex characters. Treat the
reports it returns like any other untrusted Markdown.

## Self-hosted search

If you run SearXNG for inkmoth, keep it reachable only by trusted clients: it has no authentication and its
limiter is usually off for API use.
